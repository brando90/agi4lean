# 002: examples, cost table, GPT-4 Lean4 dataset inventory, eval-loss gap

CPU only, no paid API, no key. Everything is built from the public Hugging Face org [AI4M](https://huggingface.co/AI4M) and this repo. Nothing here was Lean-checked; these are data counts and list-price estimates.

## Headline

- The paper's token counts reproduce exactly for 3 of 4 sets (MMA 10,916,097; GPT-4 MathLib4 Full Proof 71,550; Regex 124,782). The "GPT-4 LeanDojo (Individual Tactics) 1,754" does not match either public set (29 pairs = 20,261 tokens; 100 pairs = 50,145).
- Estimated GPT-4 spend for our sets is small: about $14 for the 348-pair Full Proof set, under $2 for the individual-tactics sets (lower bounds, no billing records exist). No generation log with real dollars or wall-clock was saved anywhere we can reach.
- The 4 GPT-4 Lean4 datasets "sent to BM" are not identifiable from any file, email, Slack message or slide; a candidate list is below.
- E4: no saved per-example losses exist, so no significance test is possible yet. Experiment 003 must produce them.

Tokens are GPT-2 tokens of formal + informal text, as in the paper's Table 1 (`build.py` recomputes them). Dollar columns are estimates at OpenAI list price for gpt-4 (8k), $30 per million input tokens and $60 per million output tokens, using the GPT-4 tokenizer; they are not bills.

| Method | Pairs | GPT-2 tokens (paper Table 1) | Est. GPT-4 tokens in / out | Est. API USD | Wall-clock |

| GPT-4 MathLib4 (Full Proof) | 348 | 71,550 (matches) | 343,666 / 57,863 | $13.78 | not logged |

- Full Proof input = the real 6-shot prompt (892 tokens, from `src/lean4math/dataset_gen/lean4math_dataset_gen.py`) once per pair plus the theorem; output = the ('formal','informal') tuple the prompt asks for. It counts only the 348 kept pairs, so it is a lower bound.
- Individual tactics: the zero-shot prompt is in no repo, so only the data tokens are counted (lower bound). The 29 and 100-pair sets share no pair, so they are two different generation runs.
- MMA was generated by its authors, not by us; the dollar value is only what regenerating it with GPT-4 would cost.
- Wall-clock: no log of generation time exists. `train.py` prints elapsed training time but no output was saved. Only number found: the slides say fine-tuning Gemma-2-2B on MMA took about 3 hours (hardware not stated).
- Full numbers and notes per row: `cost_table.csv`.

## (d) E4: Gemma-2-2B gpt4-more eval loss and the 0.03 gap

- Found in the slides: AI4M/gemma2-2b-gpt4-more-5-epochs, block-packing cross-entropy on UDACA/proofnet-v3-lean4 validation = 2.6845 nats (perplexity 14.65), eval code `eval_ce.py` of stair-lab/ZIP-FIT (branch bm_dev), wandb run mxyca31n (needs a wandb sign-in; not opened).
- The 1.709 (gpt4-more, 3 epochs, about 1,002 effective points) and 1.67 (MMA, 1 epoch, 84,000 points) are written in the slides without their eval set or code. The same slide lists the gpt4-more eval-loss row as "TODO". 2.6845 and 1.709 are probably not on the same eval, so they must not be compared.
- Saved per-example losses: none. The 15 AI4M model repos hold weights and configs only, no `eval_results.json`, `trainer_state.json` or loss file.
- Significance: cannot be stated. Experiment 003 must (1) evaluate gemma2-2b-gpt4-more-dataset and gemma-2-2b-mma-dataset with one eval script on the same items and save per-item (or per-block) loss, (2) ideally add several fine-tuning seeds per dataset, since the eval items are one source of noise and the fine-tuning seed is another. `paired_bootstrap.py` takes the two loss files and gives the mean gap, a 95% bootstrap interval and a paired sign-flip p-value (tested on simulated losses only). Free CPU here (1 core, 15 GB) cannot evaluate 2B-parameter models, so this needs a free GPU.
